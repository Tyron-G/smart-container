# 真实支付通道接入说明

## 当前范围

2026-05-31：管理端支付通道已补齐真实通道接入保护。

- `LOCAL_SIMULATED`：默认本地模拟通道，只记录流水，不触发外部资金。
- `ALIPAY`：已接入支付宝 SDK 退款适配器；默认关闭，配置完整且显式开启后才会请求支付宝退款接口。
- `WECHAT`：已接入微信支付 V3 官方 Java SDK 退款适配器；默认关闭，配置完整且显式开启后才会请求微信退款接口。

## 支付宝配置

通过环境变量或 Nacos 配置注入：

| 配置项 | 说明 |
| --- | --- |
| `MANAGER_ALIPAY_ENABLED` | 是否开启真实支付宝通道，默认 `false` |
| `MANAGER_ALIPAY_ENVIRONMENT` | `sandbox` 或 `production` |
| `MANAGER_ALIPAY_SERVER_URL` | 支付宝网关地址 |
| `MANAGER_ALIPAY_APP_ID` | 支付宝应用 ID |
| `MANAGER_ALIPAY_MERCHANT_PRIVATE_KEY` | 商户私钥 |
| `MANAGER_ALIPAY_PUBLIC_KEY` | 支付宝公钥 |
| `MANAGER_ALIPAY_SIGN_TYPE` | 默认 `RSA2` |
| `MANAGER_ALIPAY_ALLOW_ORDER_NO_AS_OUT_TRADE_NO` | 是否允许用本系统订单号作为支付宝商户订单号，默认 `false` |

本地或部署前可参考 `work/真实支付通道生产环境变量模板_20260531.ps1` 填写变量。模板只包含占位符，真实密钥应来自商户平台或密钥管理系统。

## 配置自检

2026-05-31：后端提供真实通道配置自检接口：

- `GET /manager/api/manager/payment/configStatus`
- 需要 `system:audit` 权限
- 只返回配置是否存在、缺失字段、环境是否合法、微信私钥文件是否存在，不返回密钥明文

本地可执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\真实支付通道配置检查_20260531.ps1
```

## 支付宝沙箱验证

2026-05-31：本地提供沙箱预下单与退款验证脚本。

生成沙箱支付二维码内容：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\支付宝沙箱预下单_20260531.ps1
```

用支付宝沙箱买家账号支付后，拿支付宝返回的交易号调用管理端退款：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\支付宝沙箱交易查询_20260531.ps1 -OutTradeNo <商户订单号>
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\支付宝沙箱退款验证_20260531.ps1 -OrderNo ORD-20260530-001 -AlipayTradeNo <沙箱支付宝交易号>
```

## 调用约束

- 真实支付宝退款必须传 `channelType=ALIPAY`。
- 推荐传 `originalChannelTradeNo`，作为支付宝原支付交易号 `trade_no`。
- 未传 `originalChannelTradeNo` 时，只有显式开启 `MANAGER_ALIPAY_ALLOW_ORDER_NO_AS_OUT_TRADE_NO=true`，才会用 `orderNo` 作为 `out_trade_no`。
- 配置不完整、环境为空、环境不是 `sandbox/production`、未开启通道、缺少原交易号时，均不会调用支付宝接口。

## 微信支付配置

通过环境变量或 Nacos 配置注入：

| 配置项 | 说明 |
| --- | --- |
| `MANAGER_WECHAT_ENABLED` | 是否开启真实微信通道，默认 `false` |
| `MANAGER_WECHAT_ENVIRONMENT` | `sandbox` 或 `production` |
| `MANAGER_WECHAT_MCH_ID` | 微信支付商户号 |
| `MANAGER_WECHAT_API_V3_KEY` | 微信支付 APIv3 密钥 |
| `MANAGER_WECHAT_MERCHANT_SERIAL_NO` | 商户 API 证书序列号 |
| `MANAGER_WECHAT_PRIVATE_KEY_PATH` | 商户 API 私钥文件路径 |
| `MANAGER_WECHAT_REFUND_NOTIFY_URL` | 退款结果通知地址，可为空 |
| `MANAGER_WECHAT_ALLOW_ORDER_NO_AS_OUT_TRADE_NO` | 是否允许用本系统订单号作为微信商户订单号，默认 `false` |
| `MANAGER_WECHAT_LOCAL_TEST_MODE` | 微信本地联调模式，默认 `false`；只验证管理端退款闭环，不请求微信真实资金接口 |

2026-05-31：本地真实微信配置文件统一放在 `work/.payment-secrets/wechat-production/`，该目录已被仓库忽略。商户平台复制值后可执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\写入微信支付剪贴板值_20260531.ps1 -Type MchId
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\写入微信支付剪贴板值_20260531.ps1 -Type AppId
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\写入微信支付剪贴板值_20260531.ps1 -Type ApiV3Key
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\写入微信支付剪贴板值_20260531.ps1 -Type MerchantSerialNo
```

商户 API 私钥文件请保存为：

```text
work/.payment-secrets/wechat-production/apiclient_key.pem
```

配置完整后启动真实微信环境：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\启动微信真实环境_20260531.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\真实支付通道配置检查_20260531.ps1
```

## 微信本地联调验证

2026-05-31：由于微信支付官方真实接口必须依赖商户平台签发的商户号、APIv3 Key、证书序列号和商户私钥，本项目新增受控的微信本地联调模式，用于在没有真实微信商户资质时验证管理端业务链路。

启动本地微信联调环境：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\启动微信本地联调环境_20260531.ps1
```

检查配置状态：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\真实支付通道配置检查_20260531.ps1
```

执行微信本地退款闭环：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\work\微信本地退款验证_20260531.ps1
```

该模式下 `channelType=WECHAT` 会返回 `SUCCESS` 并落库 `payment_operation_record`，但 `channel_message` 会明确标识“未触发微信真实资金划转”。生产真实微信退款必须关闭 `MANAGER_WECHAT_LOCAL_TEST_MODE`，并配置完整商户参数。

## 微信调用约束

- 真实微信退款必须传 `channelType=WECHAT`。
- 推荐传 `originalChannelTradeNo`，作为微信原支付交易号 `transaction_id`。
- 未传 `originalChannelTradeNo` 时，只有显式开启 `MANAGER_WECHAT_ALLOW_ORDER_NO_AS_OUT_TRADE_NO=true`，才会用 `orderNo` 作为 `out_trade_no`。
- 微信退款接口必须传原订单总金额，后端从 `order_info.pay_amount` 读取并换算为分。
- 配置不完整、环境为空、未开启通道、缺少原交易号时，均不会调用微信接口。
- 补扣不等同于退款逆操作，支付宝/微信补扣需要独立的协议扣款产品和签约号，当前真实通道只开放退款。

## 审计字段

`payment_operation_record` 增加：

- `error_code`
- `channel_request_payload`
- `channel_response_payload`

这些字段用于记录第三方请求和响应，便于排查幂等、失败和差错场景；不得写入商户私钥、APIv3 密钥或证书内容。
