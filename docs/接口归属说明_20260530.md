# smart-container 接口归属说明

> 更新时间：2026-05-30

## 1. 文档目的

本文档用于从“接口归属”的角度，对当前 `smart-container` 仓库中可见的主要接口进行分类，帮助快速判断：

- 哪些接口属于**管理端前端调用**
- 哪些接口属于**用户端调用**
- 哪些接口属于**设备端调用**
- 哪些接口属于**内部服务间调用**
- 哪些接口属于**第三方平台回调**

> 说明：本文档仅基于当前仓库代码可见内容整理，不等同于完整线上接口清单。

---

## 2. 接口归属分类标准

为了避免混淆，本文档按以下五类划分：

### 2.1 管理端接口
面向后台管理页面、运营人员、管理员使用的接口。

特点：
- 偏配置、管理、维护
- 通常不直接服务普通消费者
- 常见路径关键词：`manager`、`config`、`coupon`

### 2.2 用户端接口
面向消费者、扫码用户、移动端入口（App / 小程序 / H5 / 支付宝 / 微信）的接口。

特点：
- 与订单、用户绑定、支付、短信、鉴权相关
- 偏 C 端业务流程

### 2.3 设备端接口
面向智能货柜、设备网关、协议接入层的接口。

特点：
- 与心跳、开门、设备事件、协议处理相关
- 通常不由普通前端直接调用

### 2.4 内部服务接口
面向微服务之间调用的接口。

特点：
- 常以 Feign 接口、Feign 实现、内部桥接 Controller 形式出现
- 主要用于服务编排，不建议视为前端公开接口

### 2.5 第三方平台回调接口
面向支付宝、微信等外部平台回调。

特点：
- 不是前端页面直接调用
- 通常承接支付/签约/授权结果通知

---

## 3. 模块级接口归属概览

| 模块 | 主要接口归属 | 补充说明 |
|---|---|---|
| `container-manager` | 管理端接口 | 运营配置、后台管理 |
| `container-order` | 用户端接口 + 部分内部服务接口 | 订单、扫码、验证码、用户绑定 |
| `container-channel` | 用户端接口 + 内部服务接口 + 第三方回调接口 | 支付、短信、授权、回调 |
| `container-account` | 当前仓库中接口较少/不明显 | 更像公共账户服务 |
| `container-device` | 设备业务接口 + 内部服务接口 | 设备状态、开门、设备操作 |
| `container-communicate` | 设备端接口 + 内部桥接接口 | Netty 通信、事件接收 |

## 4. 具体接口归属说明

## 4.1 管理端接口

### 4.1.1 优惠券配置接口
#### 文件
- `container-manager/src/main/java/cn/fuguang/manager/controller/CouponController.java`

#### 接口
- `POST /manager/api/manager/coupon/addCouponConfig`

#### 归属
- **管理端接口**

#### 理由
- 路径中直接带有 `manager`
- 功能是“新增优惠券配置”
- 典型的后台运营配置行为

## 5. 当前仓库中“不明确或不显式”的接口情况

### 5.1 `container-account`

当前仓库可见代码里，`account` 模块没有明显的 controller 接口暴露。

因此可以判断：
- 它更像公共账户能力模块
- 可能主要通过 Feign / 服务内部调用服务其他模块
- 也可能真实接口定义在仓库外配置、网关层或未来扩展中

所以在接口归属上，当前只能暂归为：

- **公共账户服务**
- **间接服务用户端与管理端**
- **当前仓库内未发现明确前端接口清单**

## 7. 如何使用这份归属说明

### 如果你在做管理后台前端
优先关注：
- `container-manager`
- 与配置、运营相关接口

### 如果你在做用户侧前端
优先关注：
- `container-order`
- `container-channel`
- 与扫码、订单、支付、短信相关接口

### 如果你在做设备联调
优先关注：
- `container-communicate`
- `container-device`
- Netty/TCP 协议处理、设备事件流转

### 如果你在做后端服务编排
优先关注：
- `container-api`
- 各 `FeignServiceImpl`
- MQ listener / Redis listener

## 8. 结论

从接口归属角度看，这个项目并不是一个“单前端调用的普通后端”，而是一个典型的**多角色后端系统**：

- 有明确的**管理端接口**
- 有明确的**用户端业务接口**
- 有明确的**设备端通信入口**
- 还有大量**内部服务接口**与**第三方回调接口**

因此对它最准确的理解不是“一个后台 + 一个 App”，而是：

## **管理端 + 用户移动端 + 设备端 + 内部服务协作层**

这也是它和普通后台管理系统最大的区别。
