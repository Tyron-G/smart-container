# smart-container Git 安全配置说明

> 更新时间：2026-05-30

## 1. 文档目的

本文档用于记录当前仓库为了**防止误推送到云效（Codeup）**而做的 Git 安全配置，帮助后续维护者理解：

- 为什么默认 `git push` 会推到 GitHub
- 为什么 `origin` 当前无法直接推送
- 如何恢复云效推送（如果未来确实需要）

---

## 2. 当前仓库远程配置

当前仓库存在两个远程：

### 2.1 GitHub
- remote 名称：`github`
- fetch URL：
  - `https://github.com/Tyron-G/smart-container.git`
- push URL：
  - `https://github.com/Tyron-G/smart-container.git`

### 2.2 云效 / Codeup
- remote 名称：`origin`
- fetch URL：
  - `git@codeup.aliyun.com:63d9d9291e18eba4c4e535f4/smart-container.git`
- push URL：
  - `DISABLED_NO_PUSH_TO_YUNXIAO`

这表示：
- **可以继续从云效 fetch / pull**
- **不能直接向云效 push**

这是故意设置的安全保护，不是仓库损坏。

---

## 3. 当前 Git 安全保护策略

为了避免误把代码推送到云效，当前仓库采用了以下策略：

### 3.1 默认推送目标固定为 GitHub
当前配置：

```text
remote.pushDefault = github
```

效果：
- 直接执行 `git push` 时，默认优先推送到 `github`
- 不会优先推送到 `origin`

---

### 3.2 默认 push 行为设为 current
当前配置：

```text
push.default = current
```

效果：
- 执行 `git push` 时，默认推送“当前分支”
- 可以减少误推其他分支的风险

---

### 3.3 当前开发分支绑定到 GitHub 上游
例如当前开发分支：

```text
feat/local-dev-tooling-and-docs-20260530
```

已经绑定到：

```text
github/feat/local-dev-tooling-and-docs-20260530
```

效果：
- 在该分支执行 `git push` 时，会自然推到 GitHub 上对应分支

---

### 3.4 禁用 origin 的 push URL
当前配置：

```text
origin push URL = DISABLED_NO_PUSH_TO_YUNXIAO
```

效果：
- 即使手动执行：

```powershell
git push origin
```

也会失败，而不会真的推送到云效。

这一步是最关键的安全兜底。

---

## 4. 当前策略带来的直接效果

### 现在默认行为
```powershell
git push
```

会推送到：
- **GitHub**

### 现在危险命令的结果
```powershell
git push origin
```

会因为 push URL 被禁用而失败，**不会把代码推到云效**。

---

## 5. 查看当前配置的方法

你可以随时执行以下命令查看当前安全配置：

```powershell
git config --get remote.pushDefault
git config --get push.default
git branch -vv
git remote -v
```

正常情况下，应看到：

- `remote.pushDefault = github`
- `push.default = current`
- 当前分支上游是 `github/...`
- `origin` 的 push URL 为 `DISABLED_NO_PUSH_TO_YUNXIAO`

---

## 6. 如果未来确实需要恢复云效推送

如果未来某一天你明确需要重新推送到云效，可以恢复 `origin` 的 push URL：

```powershell
git remote set-url --push origin git@codeup.aliyun.com:63d9d9291e18eba4c4e535f4/smart-container.git
```

恢复后：
- `git push origin` 才会再次具备真实推送能力

> 建议只有在你确认要推云效时再恢复，不要长期保持可推状态。

---

## 7. 推荐使用方式

### 日常推送 GitHub
推荐只使用：

```powershell
git push
```

或者显式指定：

```powershell
git push github
```

### 不推荐的习惯
避免无意识执行：

```powershell
git push origin
```

虽然当前被禁用了，但从团队习惯上仍然不建议保留这个动作。

---

## 8. 为什么要这样做

之所以做这套安全配置，是因为当前仓库同时存在：

- GitHub 远程
- 云效 / Codeup 远程

而你的目标是：

> **只把代码推送到 GitHub，不要误推到云效**

如果不加这层保护，后续非常容易因为：
- 手滑执行 `git push`
- 没注意当前 upstream
- 沿用老习惯执行 `git push origin`

而把内容推送到不希望推送的远程。

因此当前配置本质上是一种：

## **防误操作保护措施**

---

## 9. 结论

当前仓库的 Git 安全策略可以概括为：

- **默认推送 GitHub**
- **当前分支跟踪 GitHub**
- **保留云效 fetch 能力**
- **禁用云效 push 能力**

这套配置的目标只有一个：

## **防止误把代码推送到云效**

如果没有明确需要，不建议随意恢复 `origin` 的 push URL。
