# smart-container 本地联调变更清单

> 更新时间：2026-05-30

## 1. 说明

本文档用于记录本次为了让 `smart-container` 项目能够在本地完整启动并完成基础健康检查，所做的关键环境调整、配置改造、代码修复与工具脚本补充，便于后续回顾、提交、交接与排障。

---

## 2. 本次目标

本次工作的目标包括：

1. 将各微服务切换为本地 Nacos / Redis / MySQL / RocketMQ 运行方式
2. 修复项目中阻碍本地启动的代码与配置问题
3. 拉起全部 6 个微服务
4. 补充本地启动说明文档
5. 提供一键启动 / 健康检查 / 停止脚本

## 3. 环境侧调整

### 3.1 Nacos 切换到本地环境
涉及文件：
- `container-order/src/main/resources/bootstrap.yml`
- `container-account/src/main/resources/bootstrap.yml`
- `container-channel/src/main/resources/bootstrap.yml`
- `container-communicate/src/main/resources/bootstrap.yml`
- `container-device/src/main/resources/bootstrap.yml`
- `container-manager/src/main/resources/bootstrap.yml`

调整内容：
- 将远程 Nacos 地址改为本地 `localhost:8848`
- 将各服务的 `namespace` 指向本地联调使用的命名空间

目的：
- 让所有服务都从本地 Nacos 获取配置并注册到本地注册中心

### 3.2 本地 Nacos 持久化改为本机 MySQL
环境调整内容：
- 修正本地 Nacos 的 `application.properties`
- 将原先远程数据库连接改为本地 MySQL
- 补齐 Nacos 运行所需表结构

目的：
- 确保本地 Nacos 配置可写、可持久化

### 3.3 Redis 密码链路打通
调整内容：
- 确认本地 Redis 实际使用的配置文件与真实密码
- 同步更新 Nacos 中各服务的 `spring.redis.password`

目的：
- 解决服务本地启动时 `NOAUTH` / `ERR invalid password` 问题

### 3.4 本地 RocketMQ 启动
环境调整内容：
- 使用 `D:\rocketmq-all-5.5.0-bin-release` 启动本地 RocketMQ
- 解除 `.cmd` 文件的系统阻止
- 正确设置 `ROCKETMQ_HOME`
- 启动 NameServer 与 Broker

目的：
- 满足 `device` 等模块对 RocketMQ 的依赖

## 4. 代码与配置修复清单

### 4.1 根构建修复
#### 文件
- `pom.xml`

#### 变更
- 为 `spring-boot-maven-plugin` 指定版本

#### 原因
- 避免 Maven 拉取到 4.x 插件，导致 Java 8 环境下运行 `spring-boot:run` 失败

---

### 4.2 Redis 配置修复
#### 文件
- `container-common/container-common-redis/src/main/java/cn/fuguang/common/redis/configure/RedissonConfig.java`

#### 变更
- 增加对 `spring.redis.password` 的读取
- 在 Redisson 单机配置中设置密码

#### 原因
- 原实现只设置 host/port，没有设置 password
- 导致本地 Redis 开启认证时所有依赖 Redisson 的服务无法启动

---

### 4.3 order 模块修复
#### 文件
- `container-order/src/main/resources/mapper/VerifyCodeMapper.xml`

#### 变更
- 修复错误的 `JdbcType.DATETIME`
- 修正 insert 语句的表名与字段名
- 修正实体参数类型与 SQL 语法问题

#### 原因
- 原 Mapper XML 解析失败，直接阻断 `container-order` 启动

---

### 4.4 channel 模块修复
#### 文件
- `container-channel/src/main/java/cn/fuguang/channel/ContainerChannelApplication.java`
- `container-channel/src/main/java/cn/fuguang/channel/fegin/MWFeignServiceImpl.java`
- `container-channel/src/main/java/cn/fuguang/channel/service/impl/MWChannelServiceImpl.java`
- `container-channel/src/main/resources/mapper/CustomerMapper.xml`
- `container-channel/src/main/resources/mapper/CustomerAgreementSignMapper.xml`

#### 变更
- 启动类增加 `@EnableFeignClients(basePackages = {"cn.fuguang.api"})`
- 修复短信通道实现中缺失/错误逻辑，保证可编译
- 为 `MWChannelServiceImpl` 补足接口实现
- 修正 `CustomerMapper.xml` 中错误的 `jdbcType=VARCHARw`
- 修正 `CustomerAgreementSignMapper.xml` 中错误的表名、字段映射与参数名

#### 原因
- `channel` 同时存在编译错误、MyBatis XML 错误、Feign Bean 缺失问题，导致服务无法启动

---

### 4.5 device 模块修复
#### 文件
- `container-device/pom.xml`
- `container-device/src/main/java/cn/fuguang/device/listener/config/RedisListenerConfig.java`
- `container-device/src/main/java/cn/fuguang/device/listener/redis/RedisKeyExpireListener.java`

#### 变更
- 补充 `rocketmq-spring-boot-starter` 依赖
- 将 Redis listener container bean 改为显式命名 `redisMessageListenerContainer`
- 为 Redis 过期监听配置与监听器增加条件开关：
  - `device.redis.listener.enabled`
- 在本地 Nacos 配置中将该开关设为 `false`

#### 原因
- 缺少 RocketMQ starter 时，`RocketMQTemplate` Bean 无法注入
- Redis 过期监听容器在本地启动阶段发生 `Subscription registration timeout exceeded`
- 本地联调阶段暂时关闭该监听，可换取服务稳定启动

---

### 4.6 manager 模块修复
#### 文件
- `container-manager/src/main/java/cn/fuguang/manager/ContainerManagerApplication.java`
- `container-manager/src/main/java/cn/fuguang/manager/controller/CouponController.java`
- `container-manager/src/main/java/cn/fuguang/manager/biz/CouponBiz.java`
- `container-manager/src/main/java/cn/fuguang/manager/biz/impl/CouponBizImpl.java`
- `container-manager/src/main/java/cn/fuguang/manager/service/CouponService.java`
- `container-manager/src/main/java/cn/fuguang/manager/service/impl/CouponServiceImpl.java`
- `container-manager/src/main/java/cn/fuguang/manager/mapper/CouponMapper.java`
- `container-manager/src/main/resources/mapper/CouponMapper.xml`

#### 变更
- 增加标准 `main` 方法
- 补充优惠券配置详情查询接口
- 补充优惠券配置编辑保存接口
- 补充优惠券配置分页查询接口
- 修正优惠券配置写入表名为 `coupon_config`
- 增加分页查询、详情查询、按配置 ID 更新 SQL

#### 原因
- 原启动类只有注解，没有 `main` 方法，导致 `spring-boot:run` 无法识别可用主类
- 原优惠券管理模块只有新增接口，前端列表、详情、编辑页面无法形成真实闭环
- 原 `CouponMapper.xml` 使用实体类名作为表名，不符合本地已验证的 `coupon_config` 表结构
